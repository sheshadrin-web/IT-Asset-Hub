==================================================
PART A — WALLPAPER AFTER USER PUSH
==================================================

GOAL

Whenever a new employee macOS user is successfully provisioned through User Push,
apply the currently active Miles corporate wallpaper to that employee account.

Example:

IT admin:
miles-it-support

Employee:
MPE000

macOS account:
mpe000

After provisioning:
- mpe000 receives the current active Miles wallpaper
- miles-it-support is not modified unless existing wallpaper policy already applies to it separately

IMPORTANT

Reuse the EXISTING Miles wallpaper infrastructure.

Do NOT create a second wallpaper system.

The agent already supports update_wallpaper.

Inspect the current:
- wallpaper API
- active wallpaper retrieval
- macOS wallpaper implementation
- console-user/session handling

Add a helper that can explicitly apply the current wallpaper to a specified managed employee username.

The provisioning sequence should become:

provision_user
→ create/validate standard employee account
→ write/verify employee code marker
→ mark credential ready
→ apply active corporate wallpaper to employee profile
→ return provisioning success

Wallpaper failure should NOT delete the successfully created employee account.

If user creation succeeds but wallpaper application fails:

Provisioning should still remain successful,
but report a non-secret warning such as:

"User provisioned successfully; wallpaper will retry on next policy sync."

The normal wallpaper policy should retry later.

PART B — PASSWORD POLICY
==================================================

IMPORTANT SECURITY DECISION

Do NOT make the production universal password "miles".

For development/pilot testing only, support a configurable test temporary password if needed.

Production behavior should remain secure.

Preferred production workflow:

User Push
→ secure temporary password
→ IT reveals once
→ employee receives password securely
→ employee changes password later

For password reset:

IT explicitly chooses a new TEMPORARY password through Asset Hub.

Do NOT retrieve the employee's existing password.
Do NOT display the employee's current password.
Passwords must never be recoverable.

Password reset means replacing the password with a new temporary password.
