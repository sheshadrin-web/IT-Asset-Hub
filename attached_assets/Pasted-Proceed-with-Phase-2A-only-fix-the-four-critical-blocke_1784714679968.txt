1. SESSION NEVER BECOMES ACTIVE

Current issue:

- Assisted remote sessions move from:
  requested
  ->
  approved

- But no code transitions:
  approved
  ->
  active

- The Realtime RLS policy allows only active sessions.
- As a result, the agent and viewer cannot join the channel correctly.

Required fix:

Update the database function:

issue_remote_session_token

It must:

- Validate the authenticated administrator.
- Validate tenant access.
- Validate asset and device.
- Validate that the session is approved.
- Validate that the session is not expired, ended, revoked, or failed.
- Generate the session token and channel.
- Atomically update session status to active.
- Set started_at if it is currently null.
- Return the existing token/channel response.
- Prevent duplicate activation.
- Remain safe if called more than once.

Do not loosen the Realtime RLS policy unnecessarily.

Preferred behaviour:

- Realtime access remains restricted to status='active'.
- Token generation and activation happen atomically in one trusted RPC.

Add tests for:

- approved -> active
- requested session cannot activate
- ended session cannot activate
- expired session cannot activate
- unauthorised admin cannot activate
- duplicate token request does not create conflicting state

3. ADD AGENT-SIDE SESSION END REPORTING
==================================================

Current issue:

The viewer can end a session, but when the employee, timeout, agent error, restart, or network failure ends the session:

- The agent closes the channel.
- The database is not updated.
- The session may stay approved or active.
- ended_at, ended_by, end_reason, and duration_seconds are missing.

Required database migration:

Add columns to remote_access_sessions:

- ended_by
- end_reason
- duration_seconds

Use appropriate data types and existing project conventions.

Do not drop or rename existing columns.

Create an idempotent RPC:

agent_end_remote_session

Expected inputs:

- agent token or verified device identity
- session_id
- ended_by
- end_reason
- duration_seconds

Required behaviour:

- Verify the agent/device owns the session.
- Verify tenant and asset association.
- Allow only the authorised agent or trusted backend.
- Set status='ended'.
- Set ended_at if not already set.
- Set ended_by.
- Set end_reason.
- Set duration_seconds.
- Be idempotent.
- If already ended, return the current final session state without error.
- Reject requests for another device's session.
- Reject revoked devices.

Add Edge Function route:

POST /remote-access/session/end

File:

artifacts/asset-desk/supabase/functions/agent-api/index.ts

Body:

{
  "session_id": "...",
  "ended_by": "employee|administrator|timeout|agent|network|error",
  "end_reason": "...",
  "duration_seconds": 123
}

Update the agent:

artifacts/asset-desk/agent/laptop_agent.py

- Employee clicks Disconnect
- Administrator sends end event
- Session timeout
- Network/WebSocket failure
- Capture error
- Input-handler error
- Agent shutdown
- Agent restart
- Unexpected exception

Use a single helper function such as:

_report_remote_session_end(...)

Requirements:

- Call at most once per session.
- Be safe if called more than once.
- Use a short timeout.
- Do not block shutdown indefinitely.
- Do not log tokens.
- Do not fail the agent loop if reporting fails.
- Retry once when appropriate.
- Include a clear end reason.

Add tests for:

- Employee disconnect
- Viewer disconnect
- Timeout
- Network error
- Duplicate end call
- Already-ended session
- Wrong device
- Revoked agent
